## 一、项目概述

### 1. 项目背景

（1）项目来源：在课程学习过程中，同学们缺乏一个快捷的题目练习与存储工具，故而开发此系统

（2）应用场景：日常课后习题自测与反复练习，个人优质题目手机分析整理，重点题目解答与回顾

（3）现实意义：用户可自行选择与存储练习适合自己的题目，实现问题的积累与运用

### 2. 系统目标

本系统旨在完成一个轻量级题目评测工具的开发，目前已实现以下主要目标：

刷题练习：系统能够从题库中随机抽取题目供用户练习，题目为C语言，C++语言编程题，用户可逐题作答。

答案核验：系统能够将用户提交的答案与标准答案进行自动比对，并即时反馈对错结果，帮助用户检验知识掌握情况。

数据存储：用户信息和做题记录信息存储在mysql数据库，便于随时查看，题目信息通过代码存储在problem文件中。

预期效果：

用户可通过命令行界面进行无干扰的刷题练习

每次练习后获得即时反馈，便于查漏补缺

后续将在此基础上扩展题目管理、练习记录留存等功能

### 3. 开发环境

开发工具：Visual Studio,DEV C++;

开发环境：Windows系统，运行方式：命令行终端

数据库：数据库名称：init.sql

字符集：utf8mb4

核心数据表：user（用户表）、practice_record（练习记录表）

## 四、系统实现

### 1. 关键技术

本系统实现涉及以下五项关键技术：

#### （1）HTTP服务器实现

| 项目 | 说明 |
|------|------|
| 技术方案 | 原生Windows Socket API（Winsock2） |
| 关键函数 | socket()、bind()、listen()、accept()、recv()、send() |
| 并发模型 | 多线程，每个客户端请求独立线程处理 |
| 请求解析 | 手动解析HTTP请求行、请求头、请求体 |
| 响应构造 | 按照HTTP/1.1协议构造响应报文 |

代码示意：

```cpp
// 创建socket
SOCKET server = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);

// 绑定端口
bind(server, (sockaddr*)&addr, sizeof(addr));

// 监听
listen(server, SOMAXCONN);

// 接受连接
SOCKET client = accept(server, NULL, NULL);

// 多线程处理
CreateThread(NULL, 0, handleClientThread, (LPVOID)client, 0, NULL);
```
#### （2）进程隔离与沙箱

| 项目 | 说明 |
|------|------|
| 技术方案 | Windows Job Object（作业对象） |
| 核心作用 | 限制子进程资源，确保超时后能完整终止进程树 |
| 关键步骤 | ① 创建作业对象 → ② 设置终止限制 → ③ 将进程分配到作业 → ④ 超时后终止作业 |
| 进程创建 | CREATE_NO_WINDOW标志（不显示控制台窗口） |

代码示意：

```cpp
// 创建作业对象
HANDLE hJob = CreateJobObject(NULL, NULL);

// 设置作业限制（关闭作业时终止所有进程）
JOBOBJECT_EXTENDED_LIMIT_INFORMATION jeli = { 0 };
jeli.BasicLimitInformation.LimitFlags = JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE;
SetInformationJobObject(hJob, JobObjectExtendedLimitInformation, &jeli, sizeof(jeli));

// 将进程分配到作业
AssignProcessToJobObject(hJob, pi.hProcess);

// 超时后终止整个作业
TerminateJobObject(hJob, 1);
```

### 3. 核心代码片段

#### （1）HTTP服务器启动与请求处理

```cpp
// 初始化 Winsock
WSADATA wsaData;
WSAStartup(MAKEWORD(2, 2), &wsaData);

// 创建 socket
SOCKET server = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);

// 绑定地址和端口
sockaddr_in addr;
addr.sin_family = AF_INET;
addr.sin_addr.s_addr = INADDR_ANY;
addr.sin_port = htons(3000);
bind(server, (sockaddr*)&addr, sizeof(addr));

// 监听连接
listen(server, SOMAXCONN);

// 接受客户端连接，为每个客户端创建独立线程
while (true) {
    SOCKET client = accept(server, NULL, NULL);
    CreateThread(NULL, 0, handleClientThread, (LPVOID)client, 0, NULL);
}
```
**说明：使用原生 Socket API 创建 HTTP 服务器，监听 3000 端口，多线程并发处理客户端请求。**

#### （2）代码编译实现

```cpp
string compileCode(const string& sourcePath, const string& outputPath, 
                   const string& language) {
    string cmd;
    if (language == "cpp") {
        cmd = "g++ \"" + sourcePath + "\" -o \"" + outputPath + 
              "\" -O2 -std=c++11 2>&1";
    } else if (language == "c") {
        cmd = "gcc \"" + sourcePath + "\" -o \"" + outputPath + 
              "\" -O2 -std=c11 2>&1";
    }
    
    array<char, 4096> buffer;
    string result;
    FILE* pipe = _popen(cmd.c_str(), "r");
    
    while (fgets(buffer.data(), buffer.size(), pipe) != nullptr) {
        result += buffer.data();
    }
    
    int exitCode = _pclose(pipe);
    
    if (exitCode != 0 || !fileExists(outputPath)) {
        return result.empty() ? "编译失败" : result;
    }
    return "";  // 编译成功
}
```
**说明：通过 _popen() 调用 g++/gcc 编译器，捕获编译错误输出，编译成功返回空字符串。**

#### （3）沙箱运行与超时控制

```cpp
string runProcess(const string& exePath, const string& inputFile,
                  const string& outputFile, long long timeLimitMs) {
    // 创建作业对象（用于进程隔离）
    HANDLE hJob = CreateJobObject(NULL, NULL);
    JOBOBJECT_EXTENDED_LIMIT_INFORMATION jeli = { 0 };
    jeli.BasicLimitInformation.LimitFlags = JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE;
    SetInformationJobObject(hJob, JobObjectExtendedLimitInformation, &jeli, sizeof(jeli));
    
    // 创建进程（挂起状态）
    CreateProcessA(NULL, cmdLine, NULL, NULL, TRUE,
                   CREATE_NO_WINDOW | CREATE_SUSPENDED, NULL, NULL, &si, &pi);
    
    // 将进程分配到作业对象
    AssignProcessToJobObject(hJob, pi.hProcess);
    
    // 恢复线程执行
    ResumeThread(pi.hThread);
    
    // 等待进程完成或超时
    DWORD waitResult = WaitForSingleObject(pi.hProcess, (DWORD)timeLimitMs);
    
    if (waitResult == WAIT_TIMEOUT) {
        TerminateJobObject(hJob, 1);  // 终止整个进程树
        return "TLE";
    }
    
    DWORD exitCode;
    GetExitCodeProcess(pi.hProcess, &exitCode);
    
    if (exitCode != 0) return "RE";
    return "AC";
}
```
**说明：使用 Windows Job Object 实现进程隔离，超时后终止整个进程树（防止死循环程序残留）。**

#### （4）答案比对算法

```cpp
// 读取实际输出和期望输出
string actualOutput = trim(readFile(outputFile));
string expectedOutput = trim(readFile(expectedOutputFile));

// 精确匹配
if (actualOutput == expectedOutput) {
    result.status = "AC";
    result.detail = "通过";
}
// 去除空白字符后匹配
else {
    string actualNoSpace, expectedNoSpace;
    for (char c : actualOutput) 
        if (!isspace(c)) actualNoSpace += c;
    for (char c : expectedOutput) 
        if (!isspace(c)) expectedNoSpace += c;
    
    if (actualNoSpace == expectedNoSpace) {
        result.status = "PE";   // 格式错误
        result.detail = "格式错误";
    } else {
        result.status = "WA";   // 答案错误
        result.detail = "答案错误";
    }
}
```
**说明：先精确匹配输出，若失败则去除空白字符后匹配（判断是否为格式错误）。**

#### 出现的问题：

##### 1. 错题记录后正确答案无法判别

| 项目 | 内容 |
|------|------|
| 现象 | 用户先输入错误答案，系统记录错题后；再次输入正确答案，系统仍判定为错误，无法正确判别 |
| 原因分析 | 系统记录错题时，将错误的答案数据也进行了记录且没有释放。再次输入其他答案时，系统检测到的只有错误数据，没有接收新答案 |
| 解决方案 | 记录错题时只记录错误题目的题号信息，不保存错误答案数据；每次提交时重新读取用户最新输入，确保数据正确释放 |
| 状态 | 已解决 |

##### 2. 死循环代码导致系统假死

| 项目 | 内容 |
|------|------|
| 现象 | 用户提交死循环代码（如while(1){}），系统无法跳出循环，导致整个评测系统假死、无法响应其他请求 |
| 原因分析 | 系统检测输入答案判断对错时，会将代码完整运行一遍才能判断。输入死循环代码后，程序无法正常结束，导致系统阻塞 |
| 解决方案 | 更换检测方法：使用Windows Job Object实现超时控制，设置时间限制，超时后强制终止进程树；系统检测到死循环或无意义循环时直接跳出，返回TLE（超时）并显示错误原因 |
| 状态 | 已解决 |

## 七、项目总结

### 1. 成果总结

本系统成功完成了一个轻量级在线评测系统（Online Judge）的开发与实现。系统采用B/S架构，用户通过浏览器即可访问，无需安装任何客户端软件。

在核心功能方面，系统实现了完整的刷题练习闭环：用户可在50道编程题目中自由选择，在集成Monaco编辑器（VS Code同款）中编写C/C++代码并提交，系统会自动编译运行用户代码，与标准答案进行比对，并给出AC（通过）、WA（答案错误）、TLE（超时）、RE（运行时错误）、CE（编译错误）、PE（格式错误）等六种评测结果。

在辅助功能方面，系统提供了完善的学习支持工具。错题本功能会自动记录用户未通过的题目，当用户再次提交正确答案后会自动从错题本中移除；提交历史功能记录了每一次代码提交的详细情况，方便用户回顾；统计页面通过环形图和柱状图直观展示用户的通过率、状态分布及每日提交趋势；排行榜则按通过题数对所有用户进行排序，激发学习动力。此外，系统还支持亮色/暗色两种主题的切换，满足不同使用环境的需求。

总体而言，项目按期完成了从中期控制台程序到结项Web在线评测系统的全面重构与升级，所有核心功能均正常运行，达到了预期的设计目标。

### 2. 不足与改进方向

第一：在功能扩展方面，目前系统仅支持C和C++两种编程语言，对于习惯使用Python、Java等语言的用户不够友好。后续可考虑扩展支持更多编程语言，通过调用相应的编译器或解释器完成评测，扩大系统的适用范围。

第二：部分题目数据在初期存在错误，需要人工逐题校验。后续可增加语言选择下拉框，并建立自动化的题目数据校验机制。
